# Project Context

## Purpose

The clinical record compiler compiles per-source structured clinical observations into a deterministic, fail-closed, and audit-traceable clinical document (`NURSING_RECORD_TELEGRAPHIC`). It preserves distinct certainty, missingness, and provenance representations without conflating source assertions, compiler-assigned assessments, or absent data.

## Actors

| Actor | Need | Relationship to system |
|---|---|---|
| Clinical System / EHR Ingestion | Ingest structured clinical feeds and produce standardized telegraphic nursing documentation | Upstream data provider feeding JSONL input |
| Clinical Auditor / Reviewer | Inspect compilation provenance, missingness rationale, and strict determinism audit trail | Downstream reader of generated documents and diagnostics |
| Coding Agent / Maintainer | Safely modify, extend, or verify compiler passes and contracts without violating safety invariants | Operator and maintainer working through governed specifications and tests |

## Domain Model

### Structured Fact

**Meaning:** An atomic observation received from an upstream source containing `fact_id`, `field_id`, `raw_value`, nested `provenance` (`source_kind`, `source_ref`), and optional `source_asserted_certainty`.
**Related concepts:** `SourceFactIR`, `FieldContract`, `CanonicalClinicalFact`.
**Do not confuse with:** Canonical clinical facts produced after semantic normalization.

### Source-Declared Certainty

**Meaning:** The certainty token declared directly by the upstream source (such as `confirmed` or `probable`). Preserved verbatim in `SourceFactIR.source_asserted_certainty` for audit traceability.
**Related concepts:** `source_asserted_certainty`, `CompileResult.source_asserted_certainties`.
**Do not confuse with:** Compiler-assigned clinical certainty (`ClinicalValue.certainty`), which is an independent axis and remains `UNRESOLVED` in R1.

### Compiler-Assigned Certainty

**Meaning:** The diagnostic certainty level assigned by compiler semantic rules. In R1, all normalized facts evaluate strictly to `UNRESOLVED` because automated certainty deduction rules are not approved.
**Related concepts:** `Certainty.UNRESOLVED`, `ClinicalValue`.
**Do not confuse with:** `source_kind` (provenance modality) or `source_asserted_certainty` (source assertion).

### Missingness

**Meaning:** Explicit distinction between an assessed absence (`raw_value: null` mapped to `Missingness.MISSING` with active provenance) and an unassessed observation where no fact was provided (rendered as `unknown [not_assessed]`).
**Related concepts:** `Missingness.NOT_ASSESSED`, `Missingness.MISSING`, `Missingness.NOT_APPLICABLE`.
**Do not confuse with:** Generic null values or unhandled fields.

### Provenance

**Meaning:** Traceable origin modality (`monitor`, `lab`, `clinical_note`) and source fact references (`source_fact_refs`) tracking every clinical value back to its constituent source facts.
**Related concepts:** `Provenance`, `ALLOWED_SOURCE_KINDS`, `source_fact_ids`.
**Do not confuse with:** Clinical certainty or credibility weighting.

### Policy Resolution

**Meaning:** The explicit mechanism governing clinical veto terms for admissibility. Requires either an owner-authored policy seed (`{"terms": ["term_a"]}`) or an explicit owner deferral (`DEFERRED_BY_OWNER_DECISION`).
**Related concepts:** `PolicyResolution`, `PolicyResolutionState`, `PolicySeedFault`, `UNRESOLVED_POLICY`.
**Do not confuse with:** Hardcoded mutable blacklist lists at import time.

## Core Capabilities

- Ingest and validate structured clinical feed records from UTF-8 JSONL input.
- Normalize structured observations into canonical clinical facts preserving provenance and source declarations.
- Enforce clinical policy and reference admissibility with strict fail-closed quarantine.
- Select document entries according to target document mode (`NURSING_RECORD_TELEGRAPHIC`).
- Render deterministic, byte-identical output with canonical glyphs, LF line breaks, and explicit codepoint sorting.
- Validate generated bytes independently with a byte/grammar conformance linter.

## External Systems

### Upstream Clinical Ingestion Feed

**Relationship:** Provides raw JSONL lines representing patient observations.
**Information exchanged:** JSON objects containing `fact_id`, `field_id`, `raw_value`, nested `provenance` (`source_kind`, `source_ref`), and optional `source_asserted_certainty`.
**Canonical contract/source:** `openspec/specs/input-contract/spec.md` and `src/clinical_compiler/adapters/contract.py`.

## Domain Constraints

- Zero runtime dependencies: the compiler relies entirely on Python standard library modules.
- Strict fail-closed semantics: any diagnostic emitted across any stage blocks document emission completely.
- Absolute byte determinism: identical inputs under any environment produce bit-identical SHA-256 byte outputs.
- Separation of concerns: source certainty, compiler certainty, missingness, and provenance are strictly separate axes.

## Non-Goals

- No automated derivation of clinical certainty from `source_kind` or source assertions in R1.
- No free-text parsing, NLP, fuzzy entity extraction, or unstructured clinical note synthesis.
- No persistent storage, database connections, message queues, caches, or external network services.
- No runtime agent orchestrator, external LLM calls, MCP servers, or background worker processes.
- No multi-tenant user authentication, authorization, session management, or encryption key services.
- No speculative document modes beyond `NURSING_RECORD_TELEGRAPHIC` in R1.

## Known Misinterpretations

- `source_kind` (e.g. `monitor` vs `clinical_note`) is provenance only; it does not assign `CONFIRMED` or `PROBABLE` certainty.
- `raw_value: null` is an assessed absence (`MISSING`), not an unassessed omission.
- `DocumentIR` stores only references (`clinical_fact_ref`) and presentation roles, never canonical clinical values.
- `core.policy.NEVER_AUTO_TERMS` is an immutable empty default; it is not runtime-mutable policy.
