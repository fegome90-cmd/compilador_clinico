# Tasks: clinical-compiler R1 — Working, Contract-Governed Clinical Record Compiler

## Authority & Conventions

Derives from `design.md` (normative) + the 7 domain specs; MUST NOT redefine either. Baseline commit `c6578b6`; core is frozen (additive changes only — R1's ONLY core change is the adjudicated additive `CanonicalClinicalIR` in `core/ir.py`, CRC-003 / design D10, owner adjudication 2026-08-28). Test command `uv run --no-sync pytest` (config `apply.tdd: true` — write the corpus test RED, then make it GREEN). Every `uv run` invocation in this bundle uses `--no-sync`: `uv` must never auto-sync the environment against the no-install side-effect budget; if `--no-sync` fails because the environment is out of sync, the outcome is recorded `UNKNOWN` (terminal, gate-blocking), never repaired by installing. Each task references its spec domain + design section. Every phase ends at its measured gate; a BLOCKED gate enumerates failures and halts. Phase outcomes use the contract result vocabulary — `done | partial | blocked | failed` (see Result Vocabulary & Per-Phase Report below); "success" is never claimed unevidenced.

## Side-Effect Budget (all phases — prevention + detection)

**Prevention (allowlist).** Admissible ONLY: writing declared files inside the repository; running the existing provisioned toolchain (`pytest`, `ruff`, `mypy`) against it; read-only git/inspection commands. Prohibited in EVERY phase: creating virtual environments; installing/upgrading/uninstalling packages; writing outside the repository; starting/stopping any process, service, or daemon; network access. Phase 0 additionally prohibits ANY source-file mutation — observation only; if a verification command would require an environment change (e.g. dependency sync), its outcome is recorded `UNKNOWN` (terminal), never achieved by installing — and an `UNKNOWN` outcome is gate-blocking (task 0.3: it can never yield a PASS).

**Detection (evidence).** Every phase captures BEFORE/AFTER evidence: tracked-tree `git status`/`git diff`, `uv.lock` hash, installed-package listing, repository file manifest. Each evidence capture is stamped with a run ID (`clinical-compiler-r1/<phase>/<sequence>`) and a per-capture UTC timestamp (ISO-8601) — granularity is per capture, not per date — so repeated captures within one phase are orderable and attributable. A phase whose snapshots differ outside its declared writes fails the budget gate. Snapshots alone are not proof — the allowlist binds independently; both must hold.
